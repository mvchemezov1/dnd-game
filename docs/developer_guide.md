## 1. Введение

Настоящее руководство предназначено для системных администраторов, DevOps-инженеров и технических специалистов, отвечающих за развёртывание, настройку, мониторинг и поддержку серверного ПО **DnD Game** – многопользовательской RPG на базе Event Sourcing и CQRS.

В документе описаны системные требования, процедуры установки, настройки, резервного копирования, мониторинга и обновления приложения.

## 3. Установка

### 3.1. Локальная установка (для разработки)

1. **Установите .NET SDK 8.0** с официального сайта Microsoft.
2. **Установите PostgreSQL 16**:
   - Windows: скачайте инсталлятор с [postgresql.org](https://www.postgresql.org/download/windows/)
   - Ubuntu: `sudo apt install postgresql-16`
3. **Клонируйте репозиторий**:
   ```bash
   git clone https://github.com/ваш-аккаунт/dnd_game.git
   cd dnd_game
   ```
4. **Настройте строку подключения** в `appsettings.Development.json` (или через `user-secrets`):
   ```json
   "ConnectionStrings": {
       "DefaultConnection": "Host=localhost;Port=5432;Database=dnd_game;Username=postgres;Password=ваш_пароль"
   }
   ```
5. **Установите секрет JWT**:
   ```bash
   dotnet user-secrets set "Token:Secret" "случайная_длинная_строка"
   ```
6. **Запустите миграции** (выполняются автоматически при первом запуске).
7. **Запустите приложение**:
   ```bash
   dotnet run
   ```

### 3.2. Установка через Docker (рекомендуемый способ для продакшена)

1. **Убедитесь, что Docker и Docker Compose установлены**.
2. **Клонируйте репозиторий**.
3. **Настройте переменные окружения** в файле `.env` (см. раздел 4).
4. **Запустите контейнеры**:
   ```bash
   docker compose up -d
   ```
   Будут подняты:
   - PostgreSQL (с volume для постоянного хранения)
   - Приложение (на порту 5000)
   - Redis (опционально)
   - RabbitMQ (опционально)
5. **Проверьте логи**:
   ```bash
   docker compose logs -f app
   ```

### 3.3. Установка в production (без Docker)

1. **Установите .NET Runtime 8.0** на сервере.
2. **Установите PostgreSQL, Redis, RabbitMQ** (если нужны).
3. **Скопируйте бинарные файлы** (после сборки `dotnet publish -c Release -o ./publish`).
4. **Настройте переменные окружения** (см. раздел 4).
5. **Запустите приложение**:
   ```bash
   cd /opt/dnd_game
   dotnet dnd_game.dll
   ```
   Для production рекомендуется использовать systemd или Supervisor.

## 4. Настройка переменных окружения

Все настройки приложения читаются из **переменных окружения** (приоритет выше, чем `appsettings.json`). Это удобно для контейнеризации и безопасности.

| Переменная | Описание | Пример |
|------------|----------|--------|
| `ASPNETCORE_ENVIRONMENT` | Окружение (`Development`, `Staging`, `Production`) | `Production` |
| `ConnectionStrings__DefaultConnection` | Строка подключения к PostgreSQL | `Host=postgres;Port=5432;Database=dnd_game;Username=postgres;Password=secure123` |
| `ConnectionStrings__Redis` | Строка подключения к Redis (если используется) | `redis:6379` |
| `ConnectionStrings__RabbitMQ` | Строка подключения к RabbitMQ (если используется) | `amqp://guest:guest@rabbitmq:5672` |
| `Token__Secret` | Секретный ключ для подписи JWT (обязательно!) | `очень_длинная_случайная_строка_не_менее_32_символов` |
| `CORS__AllowedOrigins__0` | Разрешённые источники CORS (можно несколько) | `https://my-frontend.com` |
| `APP_URL` | URL, на котором слушает приложение | `http://0.0.0.0:5000` |
| `RateLimiting__Enabled` | Включить лимитирование запросов | `true` |
| `Serilog__MinimumLevel__Default` | Уровень логирования по умолчанию | `Information` |

**Важно:** Секрет `Token__Secret` должен быть длинным (не менее 32 символов) и храниться в защищённом месте (не в репозитории). Для его генерации можно использовать:
```bash
openssl rand -base64 32
```

## 5. Управление пользователями и ролями

В системе реализованы три роли:

| Роль | Описание |
|------|----------|
| `Player` | Обычный игрок, может управлять своими персонажами, участвовать в боях и квестах. |
| `GameMaster` | Мастер подземелий, управляет кампаниями, NPC, боями, может редактировать любые данные в своей кампании. |
| `Admin` | Полный доступ ко всем функциям системы, включая панель разработчика и управление пользователями. |

### Добавление/изменение ролей через БД

Роли хранятся в таблице `users` в колонке `global_role`. Чтобы изменить роль пользователя, выполните SQL-запрос:

```sql
UPDATE users SET global_role = 'GameMaster' WHERE username = 'имя_пользователя';
```

Допустимые значения: `Player`, `GameMaster`, `Admin`.

### Добавление пользователя вручную

Для добавления пользователя через SQL необходимо также создать запись с хешем пароля. Рекомендуется использовать API регистрации, но при необходимости можно вставить запись:

```sql
INSERT INTO users (id, username, email, password_hash, global_role, is_active)
VALUES (
    gen_random_uuid(),
    'newuser',
    'newuser@example.com',
    'хеш_пароля_(PBKDF2)',
    'Player',
    true
);
```

> **Внимание:** пароль должен быть хеширован с использованием PBKDF2 (см. код `PasswordHasher`). Для упрощения используйте API `/api/auth/register`.

## 6. Резервное копирование и восстановление

### 6.1. Резервное копирование PostgreSQL

Создайте скрипт для ежедневного бекапа (например, через cron):

```bash
#!/bin/bash
BACKUP_DIR="/var/backups/dnd_game"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="dnd_game"
DB_USER="postgres"
DB_HOST="localhost"

mkdir -p $BACKUP_DIR
pg_dump -h $DB_HOST -U $DB_USER -Fc $DB_NAME > $BACKUP_DIR/dnd_game_$DATE.dump

# Удаляем бекапы старше 30 дней
find $BACKUP_DIR -name "*.dump" -mtime +30 -delete
```

### 6.2. Восстановление из бекапа

```bash
pg_restore -h localhost -U postgres -d dnd_game /var/backups/dnd_game/dnd_game_20260818_120000.dump
```

### 6.3. Резервное копирование файлов конфигурации

Сохраняйте `appsettings.json`, `.env` и другие конфигурационные файлы в отдельное хранилище (например, в S3 или Git-репозиторий).

### 6.4. Восстановление всего стека (Docker)

Если вы используете Docker Compose, данные PostgreSQL хранятся в volume `dnd_game_pgdata`. Для бекапа volume:

```bash
docker run --rm -v dnd_game_pgdata:/data -v $(pwd):/backup alpine tar czf /backup/pgdata_backup.tar.gz -C /data .
```

Восстановление:

```bash
docker run --rm -v dnd_game_pgdata:/data -v $(pwd):/backup alpine tar xzf /backup/pgdata_backup.tar.gz -C /data
```

## 7. Мониторинг и логирование

### 7.1. Логирование (Serilog)

Приложение пишет структурированные логи в:
- **Консоль** (всегда)
- **Файлы** в папке `logs/` (если настроено)

Файлы логирования ротируются ежедневно и хранятся 30 дней.

Просмотр логов (локально):

```bash
tail -f logs/dnd_game-*.txt
```

В Docker:

```bash
docker compose logs -f app
```

### 7.2. Метрики

Встроена поддержка метрик (через `IMetricsCollector`). Метрики экспортируются через эндпоинт `/metrics` (если настроен Prometheus) или логируются в консоль.

Для интеграции с Prometheus добавьте sink:

```csharp
.WriteTo.Prometheus("http://localhost:9090/metrics")
```

### 7.3. Health-чеки

Эндпоинт `/health` (или `/api/dev/health`) возвращает статус приложения, базы данных, RabbitMQ и Redis.

### 7.4. Настройка алертов

Рекомендуется настроить мониторинг для:
- Ошибок в логах (сбор через Loki или Elasticsearch).
- Долгих запросов к БД (более 500 мс).
- Конфликтов версий (`dnd.eventstore.concurrency_conflict`).
- Критических ошибок (логгер с уровнем Error).

## 8. Обновление приложения

### 8.1. Обновление через Docker (рекомендовано)

1. Остановите контейнеры:
   ```bash
   docker compose down
   ```
2. Скачайте новую версию образа:
   ```bash
   docker compose pull app
   ```
3. Примените миграции (если есть):
   ```bash
   docker compose run --rm app dotnet dnd_game.dll --migrate
   ```
   Или они выполнятся автоматически при старте.
4. Запустите контейнеры заново:
   ```bash
   docker compose up -d
   ```

### 8.2. Обновление без Docker

1. Остановите приложение (через systemd или Ctrl+C).
2. Замените бинарные файлы (`dotnet publish` или скопируйте новые).
3. Запустите приложение снова.
4. При необходимости выполните миграции вручную (DbUp выполнит автоматически при старте).

### 8.3. Откат версии

- **В Docker**: переключитесь на предыдущий тег образа и перезапустите.
- **Без Docker**: восстановите предыдущую версию бинарных файлов и конфигурации.

## 9. Устранение неполадок

### Ошибка подключения к PostgreSQL

- Проверьте, что PostgreSQL запущен: `systemctl status postgresql`
- Проверьте строку подключения и доступность порта 5432.
- Убедитесь, что база данных создана (`dnd_game`).

### Ошибка JWT (Token:Secret не задан)

- Приложение падает при старте, если секрет не задан или равен плейсхолдеру.
- Установите переменную `Token__Secret` или используйте `dotnet user-secrets`.

### WebSocket не работает

- Убедитесь, что `app.UseWebSockets()` присутствует в `Program.cs`.
- Проверьте, что обратный прокси (nginx) настроен на поддержку WebSocket (заголовки `Upgrade` и `Connection`).

### Высокая задержка при записи событий

- Проверьте нагрузку на PostgreSQL (CPU, I/O).
- Убедитесь, что индексы созданы (см. миграции).
- Рассмотрите увеличение `max_connections` и `pooling`.

### Медленная работа проекций

- Включите кеширование Redis (если ещё не включено).
- Проверьте TTL для кеша (настраивается в `appsettings.json`).

# Dungeon Master Guide

Руководство для Мастера подземелий (DM/GM): как вести кампанию через инструменты этого сервера — от
входа в систему до принудительных правок мира и отмены ошибочных действий игроков.

---

## 1. Роль и доступ

При регистрации выбирается роль `GameMaster` (в `POST /api/auth/register`, поле `role`). Некоторые
операции (например, точная установка золота персонажу — `PUT /api/characters/{id}/gold`) доступны
только ролям `Admin` и `GameMaster`. Роль `Admin` через публичную регистрацию получить нельзя — её
выдают вручную на уровне базы/администрирования.

Консольные DM Tools (`presentation/dm_tools/dm_ui.cs`) — отдельный интерфейс, рассчитанный на то, что
им управляет сам процесс сервера или отдельный клиент с прямым доступом к шине команд, а не обычный
HTTP-клиент игрока.

---

## 2. Меню инструментов Мастера (`DmUi`)

После запуска показывается меню с пунктами:

1. **Campaign Overview** — название кампании, день/час/минута, погода, текущий акт, список открытых
   регионов, глобальные флаги (`GlobalFlags`).
2. **Party Status** — все персонажи: уровень, раса/класс, HP/AC, статус (`Alive` / `Dying` / `Stable`
   / `DEAD`), активные состояния.
3. **Combat Tracker** — по ID боя: раунд, активность, участники с инициативой, HP и меткой текущего
   хода (`<= CURRENT`).
4. **Quick Actions** — по ID персонажа: нанести урон (с типом урона), вылечить, наложить/снять
   состояние.
5. **Spawn Monster / NPC** — создать нового персонажа (имя + максимум HP), получить его ID.
6. **Manage Quests** — список квестов кампании со статусами; переключение
   `Active -> Completed -> Failed`.
7. **World State** — продвинуть время (в минутах) или сменить погоду.
8. **Inspect Character** — полная карточка персонажа: HP, AC, скорость, опыт, бонус мастерства,
   характеристики, навыки, состояния, сопротивления.

Каждое действие в этом меню — обычная доменная команда, отправленная через `ICommandBus`, то есть оно
так же сохраняется как событие в Event Store и видно в общем аудите игры.

## 3. Принудительные изменения — `OverrideCommands`

Класс `presentation/dm_tools/override_commands.cs` даёт точечные "административные" операции поверх
обычных команд — удобно вызывать из кода DM-инструментов или собственного UI Мастера:

| Категория | Методы |
|---|---|
| Жизнь и смерть | `ForceKill`, `ReviveCharacter(hp = 1)` |
| Предметы и золото | `GrantItem`, `RemoveItem`, `GrantGold`, `SetGold` |
| Характеристики и уровень | `SetAbilityScore`, `SetLevel`, `GrantExperience` |
| Состояния | `ApplyCondition`, `RemoveCondition`, `ClearAllConditions` |
| Перемещение | `TeleportCharacter` (мгновенно), `MoveCharacter` (обычное перемещение) |
| Бой | `StartCombat`, `EndCombat`, `AddToCombat`, `RemoveFromCombat` |
| Кампания | `SetGlobalFlag`/`RemoveGlobalFlag`, `ChangeFactionReputationCommand`, `CompleteQuest`/`FailQuest` |
| Время и погода | `AdvanceTime`, `ChangeWeather` |
| Спаун | `SpawnMonster(templateId, x, y, name?, maxHp?)` |
| Восстановление | `ResetCharacter` — снимает все состояния, лечит до максимума, воскрешает при необходимости |

Все эти операции **немедленно** записываются в Event Store как обычные события — отмена (см. ниже)
возможна, но не автоматическая: Мастер должен явно вызвать Undo.

---

## 4. Отмена действий — `DmUndoManager`

`presentation/dm_tools/undo_manager.cs` оборачивает `infrastructure/undo/undo_command.cs`:

- `RecordAndExecute(command, userId, sessionId)` — выполняет команду и, если она реализует
  `IUndoableAction`, кладёт её в стек отмены для текущей игровой сессии.
- `Undo(sessionId, userId)` / `Redo(sessionId, userId)` — отменить/повторить последнее записанное
  действие.
- `ForceUndoLastPlayerAction(sessionId, gmUserId)` — Мастер принудительно отменяет последнее действие
  **любого** игрока в сессии, даже если инициировал его не он сам.
- `GetLastUndoDescription` / `GetLastRedoDescription` — человекочитаемое описание того, что будет
  отменено/повторено, для UI.
- `ClearSessionHistory(sessionId)` — очистить стек отмены (например, при смене сцены/боя).

Не все команды поддерживают отмену — только те, что реализуют `IUndoableAction`. Для остальных Undo
молча ничего не делает (сохраняется отладочный лог), и правку придётся выполнять вручную встречной
командой.

## 5. Управление боем

1. Создайте бой (`Spawn` персонажей при необходимости, затем `StartCombat` со списком ID участников).
2. `CombatSaga` (см. [`event_sourcing.md`](./event_sourcing.md#8-саги-domainsagas)) автоматически:
   собирает инициативу у всех участников, сортирует их, ведёт раунды и ходы.
3. Урон/лечение/состояния можно применять как через обычные команды боя (`/api/combat/{id}/damage`
   и т. д.), так и через Quick Actions в `DmUi`, если это происходит вне формальных ходов.
4. Бой завершается автоматически, когда все оставшиеся участники принадлежат одной стороне (сага сама
   это отслеживает), либо вручную через `EndCombat`.

## 6. Управление квестами и кампанией

- Создание квеста: список целей (`Objectives`) с прогрессом и требуемым прогрессом, список наград
  (опыт, золото, предметы, изменение репутации фракции), список участников.
- Статусы квеста: `Available -> Active -> (Completed | Failed | Abandoned)`.
- Продвижение цели квеста — `UpdateQuestObjectiveCommand` (пометить выполненной или обновить
  `currentProgress`).
- Глобальные флаги кампании (`SetGlobalFlag`/`RemoveGlobalFlag`) — удобный способ хранить состояние
  сюжета ("убил_дракона" = "true"), которое читают скриптовые триггеры (`infrastructure/ai/script_engine.cs`)
  и диалоги NPC.
- Время и погода кампании управляются отдельно от реального времени — Мастер продвигает их вручную
  (`AdvanceTime` в минутах, `ChangeWeather`).

---

## 7. Важные предостережения

- Все изменения через DM-инструменты **сразу** попадают в Event Store — это не "черновик", а реальные
  игровые события, видимые проекциям, WebSocket-подписчикам и сохраняемые в истории.
- Undo не гарантирован для произвольной команды — полагайтесь на него только для команд, явно
  поддерживающих `IUndoableAction`, иначе заранее продумайте компенсирующее действие.
- `SetGold`/точная установка ресурсов — мощный инструмент, доступный только `Admin`/`GameMaster`;
  используйте `AddGold`/`SpendGold` для обычной игровой экономики, а `SetGold` — для явных правок.
- Спаун через `SpawnMonster` создаёт полноценного `CharacterAggregate` (тот же тип агрегата, что и у
  игроков) — NPC и монстры используют ту же модель здоровья/состояний/боя, что и персонажи игроков.
